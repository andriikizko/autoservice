# Автосервіс: застосунок для мереж СТО

Робоча назва демо-бренду: **«Ваш Сервіс»** (підставляється під бренд мережі).
Власник проєкту: Бартез (andriikizko). Частина напрямку **LTV Pulse**.

> Статус рішень: усе нижче — погоджене в обговоренні. Остаточно «погоджено» — тільки там, де це прямо сказано.
> Правило роботи: нічого не починати без команди **«Виконуй»**.

## 1. Суть продукту

Мережа СТО щомісяця платить за контекстну рекламу, щоб знову купувати того самого клієнта.
Застосунок робить так, що клієнт сам повертається: знає, що і коли міняти, отримує нагадування і записується в один тап.

Аргумент для власника: разовий платіж за застосунок окупається за 2–3 місяці на перших 300–400 постійних клієнтах / першій тисячі встановлень.
«Ви не отримуєте кота в мішку — ще одну рекламну кампанію. Ви отримуєте продукт, яким користуються саме ваші клієнти.»

Сильна сторона — не сам застосунок, а **правильні пуші**: сегменти, комунікація, повторні продажі.

## 2. Бізнес-модель

- **Застосунок** пишемо і віддаємо клієнту повністю, **з власним бекендом**. Він живе і без нас.
- **CRM / сервіс аналітики та сегментів** — інтелектуальна власність Бартеза, не продається. Доступ за підпискою (перший рік у пакеті). Не продовжили — застосунок працює, але без CRM-аналітики й сегментів.
- Мета: CRM-сервіс згодом продавати по всьому світу.
- Ціна: **€5 000 за замовлення**. Ціль: **3–4 замовлення на місяць**. Роботу робить сам.
- Референс моделі продажу: mentortools.com (white-label застосунок + підписка).

## 3. План запуску (зафіксовано)

1. **Лендінг** — не про СТО конкретно, а про застосунки для бізнесу, які вирішують біль бізнесу через вирішення болі клієнта.
2. **Прототип** Telegram Mini App під СТО — з ним ідемо до мереж. Один нейтральний прототип для всіх (не під одного «найкращого» ліда — вгадати, хто купить, неможливо).
3. **Telegram-канал** — прогрів тих, хто не купив одразу, потім дотискаємо.
4. Розсилка по всій базі лідів.

## 4. Формат і стек

- **PWA + Telegram Mini App**, одна кодова база.
- Стек як у numerology-bot: React + PWA на **Vercel**, бекенд **Firebase** (Cloud Functions, Firestore), адмінка окремим проєктом на Vercel. Код у GitHub (andriikizko).
- Публікація в App Store / Google Play — наступний етап, окремі гроші.

## 5. Дизайн

- Орієнтир: **Монобанк** (чисті великі картки, мінімум зайвого).
- **Темна тема**, **салатовий акцент**.
- Головна: зверху картка авто; кілька авто перемикаються свайпом, як картки в Монобанку.

## 6. Екрани застосунку (8)

1. **Вхід** — через Telegram в один тап; ім'я, телефон, місто.
2. **Додати авто** — марка, модель, рік, двигун, коробка, держномер, пробіг → регламент ТО підтягується автоматично.
3. **Головна** — картка авто (пробіг, стан авто %, OBD), швидкі дії, «потребує уваги», останній візит, бонуси.
4. **Регламент** — усі вузли: прострочено / скоро / в нормі, з кнопкою «Записатись» біля кожного.
5. **Мій гараж** — історія візитів: що міняли, на якому пробігу, сума; відкладені роботи.
6. **Запис** — місто, СТО, послуга, день, час. Підтвердження в Telegram.
7. **Бонуси** — баланс, кешбек, списання до 30% чеку, запрошення друга.
8. **Профіль** — сповіщення, OBD-датчик, мої дані.

## 7. Ключова механіка: регламент + пробіг + пуші

- При додаванні авто підтягується заводський регламент: вузли та інтервали (км і місяці).
- Клієнт вбиває пробіг — бачить, що треба зараз, через 3 000 км, через рік. Сортування за терміновістю (червоне / жовте / зелене). Рахується те, що настане раніше: кілометри чи місяці.
- Відкладені роботи від майстра («ще походить, міняти через 2 місяці») теж у списку.
- **Усе синхронізується в CRM** (і в користувача, і в CRM).
- **Раз на 2 місяці пуш:** «вбийте пробіг» (+100 ₴ бонусами). Клієнт вбиває → у CRM видно, що горить → другий пуш: «час міняти оливу, є вікно завтра» → запис в один тап. Це двигун повторних продажів.

### OBD-датчик
- Датчик ~1 000 грн рахує пробіг сам → повна прив'язка.
- **У прототипі тільки показуємо, ніби він підключений** (на моках). Реальну інтеграцію вирішуємо після продажу.

### Регламенти ТО — джерело даних
- Збирати базу вручну не потрібно: є платні API з OEM-регламентами за маркою/моделлю/роком або VIN (Vehicle Databases, Vehicle Finder, DataOne та ін.).
- Ціни відкрито не публікують; є безкоштовний старт (у Vehicle Databases — 15 кредитів), далі pay-as-you-go або підписка.
- Запит робиться один раз при додаванні авто, далі регламент зберігається в нашій базі.
- Для прототипу — моки; для мережі — API або їхні нормативи з CRM.

## 9. Статус

**Готово:**
- Дослідження ніші, база лідів, аргументація, бізнес-модель.
- Механіка регламент + пробіг + пуші.
- Клікабельний HTML-прототип усіх 8 екранів → `prototype/index.html` (також опублікований як артефакт у claude.ai).

**Не готово:**
- Перенесення прототипу в робочий React-проєкт на Vercel + Firebase.
- Лендінг.
- Telegram-канал.
- Кабінет СТО (CRM: база клієнтів, сегменти, пуш-сценарії).
- Презентація для ЛПР.
- Ліди: Луцьк, Тернопіль, Вінниця, Житомир.
